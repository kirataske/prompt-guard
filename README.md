# Швидкий старт

Примітка: Рекомендується використовувати [`yarn`](https://yarnpkg.com) у якості пакетного менеджеру.

1. Встановіть залежності, виконавши:

```bash
yarn
# або ж
npm i
```

2. Створіть файл .env у корені проєкту, за зразком з .env.example та встановіть відповідні значення параметрів.
   <br> [Про змінні оточення.](#змінні-оточення)
   <br> [Про те як отримати ключ Gemini API.](https://ai.google.dev/gemini-api/docs/get-started)

3. За бажання змініть [параметри проксі](#configts) під Ваші вподобання.

4. Для запуску виконайте:

```bash
yarn run build && yarn run start
```

# Основний функціонал

- Прийом та аналіз користувацьких команд перед передачею до ЛЛМ.
- Передача вводу LLM на обробку після підтвердження їх безпечності.
- Перешкоджання виконанню потенційно небезпечних команд.
- Журналювання й передача клієнту інформації про аналіз потенційно небезпечних команд.

# Додатково

Проксі має обмеження на запити, які можна налаштувати у [файлі конфігурації](#configts). Завмовчки проксі встановлює такі обмеження на запити:

- Не більше 5 запитів на хвилину для генерації контенту.
- Не більше 20 запитів на день для генерації контенту.
- Не більше 100 запитів на 15 хвилин для отримання збережених інцидентів.

Також проксі кешує ідентичні запити та повʼязані з ними інциденти, якщо такі було зафіксовано.
<br>Кешування базується на зберіганні обчисленої геш-суми користувацького запиту та попередньо згенерованої відповіді (або інциденту, що спричинив запит).
<br>Якщо проксі знаходить ідентичний результат у базі, замість звичного процесу обробки запиту проксі повертає збережений результат з БД (або згенерований результат, або повʼязаний із запитом інцидент).
<br>Кешування запитів є абсолютним, тобто той самий запит із незначними змінами все одно вважається окремою сутністю.

(була ідея використати Full Text Search, щоб уникнути абсолютизму та зменшити прецеденти для зберігання запитів у БД, проте для такого типу задач може не згодитись).

# Налаштування проєкту

## Змінні оточення

Файл змінних оточення (environment variables) містить у собі наступні поля:

- `APPLICATION_PORT` - порт, який проксі буде слухати (можливо варто перемістити у основний файл)
- `DETECTOR_MODEL_URL` - місцезнаходження API моделі-детектора інʼєкцій.
- `GEMINI_API_KEY` - ключ до Gemini API.

Вони є ключовими для проксі; за їх відсутності проксі гарантовано впаде.

## `config.ts`

[config.ts](src/config/config.ts) містить у собі основну частину налаштунків проксі. Пояснення стосовно параметрів знаходяться у самому ж файллі.

# API проксі

## Загальні деталі

Формат відповіді серверу у більшості випадків буде таким:

```json
{
    "status": "рядковий код стану",
    "message": "читаєме значення статусу, якщо відмінний від 'ok'",
    ...додаткові дані (основні у випадку успішного запиту)
}
```

Поле `status` присутнє у всіх випадках відповідей від серверу, коли як інші поля можуть бути присутні чи відсутні в залежності від результату.
<br>За нормальних умов поле стану завжди матиме код `ok`, у іншому випадку `status` матиме унікальний для помилки, що виникла, код.
<br>Разом з унікальним станом надається поле `message` з читаємим поясненням стану.

## Загальні відповіді від серверу:

1. При досягненні денного ліміту на запити:

   - HTTP код: 429
   - Тіло відповіді:

```json
{
   "status": "genai_daily_limitreached",
   "message": "daily limit has been reached, return in 24 hours when limit resets",
},
```

2. При досягненні ліміту на запити протягом хвилини:

   - HTTP код: 429
   - Тіло відповіді:

```json
{
  "status": "genai_minute_limitreached",
  "message": "too many requests per minute, please try again"
}
```

3. При досягненні ліміту на отримання записів журналу інцидентів:

   - HTTP код: 429
   - Тіло:

```json
{
   "status": "incidentlogs_limitreached",
   "message": "too many incident log requests, please try again later.",
},
```

4. Помилка серверу:

   - HTTP код: 500
   - Вигляд тіла:

```json
{
  "status": "internal_err_occured",
  "message": "..."
}
```

## Генерація контенту

**Шлях**: `/`
<br>**Метод**: `POST`
<br>**Тіло запиту**:
<br>Формат: JSON (`application/json`)
<br>Поля:

- `userIp`: дійсна адреса формату IPv4.
- `prompt`: команди на виконання LLM (обмеження у 1000 символів, [налаштовуване](#configts))

<br>**Відповіді**:

1. При успішному виконанні запиту:

   - HTTP код: 200
   - Вигляд тіла:

```json
{
  "status": "ok",
  "response": "generated response"
}
```

2. При недотриманні вимог форми:

   - HTTP код: 400
   - Вигляд тіла:

```json
{
    "status": "invalid_form",
    "message": "invalid form",
    "formErrors": [ ... ],
    "fieldErrors": { ... }
}
```

3. При виявленні інʼєкції в запиті:

   - HTTP код: 403
   - Вигляд тіла:

```json
{
    "status": "injection_detected",
    "message": "prompt injection was detected",
    "incident": {
        "id": unique number,
        "userIp": ip address,
        "attackType": which attack was attempted,
        "severity": how severe attempt was,
        "verdict": blocked or considered as suspicious,
        "segment": where injection was detected
    }
}
```

**Шлях**: `/incidents`
<br>**Метод**: `GET`,
<br>**Відповіді**:

   - HTTP код: 200
